## 0. 技能定位（一句话）
**法拍 + 国资（国有资产处置）+ 社会拍卖** 三类拍卖/资产处置标的统一猎手。
**已剔除**：贝壳、安居客、58同城、京东法拍；**普通二手房明确不做交叉验证、不接入**（用户 2026-09-03 明确："不需要二手房做交叉验证，直接再公拍网/联交所等网站抓国有资产或社会拍卖房源"）。
**所有标的必带类型标记**：`listing_type`（法拍/国资/社会拍卖）+ `auction.status`（挂牌中/竞价中/已成交/已流标/已结束 等）。法拍额外带 `auction.stage_round`（一拍/二拍/三拍/变卖/重新拍卖）。
**集成源**：阿里法拍、公拍网、重庆联交所，+ 中拍平台/北交所/上海联交所（浏览器渲染档，待验证）。
**代码级安全网**：`_common.DENY_DOMAINS` 域名黑名单对"自动抓取路径已彻底取消"的站点硬拦截（如原诉讼资产网域名），`fetch_page.py` 一律退出码 3（`--no-robots` 亦无效），`download_assets.py` 跳过其附件下载；**仅保留用户人工取证解析**（用户提供 HTML → `extract_page.py` 本地解析）。要恢复须先删黑名单并更新全套文档。
**联交所 / 公拍网直接抓国资与社会拍卖**：不再局限于司法拍卖（此前误以为联交所只含国资、无司法拍卖价值，现已扭转——联交所全量 feed 本就以国资/社会拍卖为主，本就是用户要的"普通房源"替代）。

## 3. 重庆联交所：表面 SPA，实为公开 JSON API（重要）
- **2026-09-07 更新：urllib 直连 API 已被 WAF 拦截**（67 字符风控壳页，fetch_page 判 BLOCKED），但 **agent-browser 打开 cquae.com 后同源 fetch 正常**——该源现在走"浏览器内 eval fetch"路径：`agent-browser open https://www.cquae.com/` → `eval "(async function(){var r=await fetch('/api/trade/project/...');...})()"`。
- 表面是 Vue SPA（静态请求只返回 ~1KB 空壳），后端 JSON API 无需登录。
- **列表接口**：`GET https://www.cquae.com/api/trade/project/projectPageQuery?page=1&size=20&projectType=31`
  - `projectType=31` 房产 / `34` 车辆等物权类。
- **详情接口**：`GET https://www.cquae.com/api/trade/project/projectDetailQuery?id=<projectId>`
- **三类标的怎么区分（`classify_listing_type`，2026-09-03 落地）**：
  - **法拍**：`serviceOrgName` 含"司法拍卖"（如"重庆联交所集团司法拍卖服务中心"）。
  - **国资**：`serviceOrgName`/标题含"国资/国有/资产处置/产权交易/公共资源/央企"等（联交所大量此类，如"产权交易分中心"）。
  - **社会拍卖**：其余非司法、非国资的公开拍卖（设备/股权/废旧物资等）。
  - `keyword=司法拍卖` 参数被服务端忽略，别靠它筛选。
- **默认全量抓取**（不止法拍）：`parse_cquae_json()` 直接按上述规则打 `listing_type`，不再默认只留法拍；`--judicial-only` 仅保留法拍子集。实测 40 条样本 → 国资 12 / 社会拍卖 28 / 法拍 0（该页无司法拍卖），分类正确。
- **代码落地**：`extract_page.py` 有 `parse_cquae_json()` + `classify_listing_type()` + `--judicial-only` 开关；检测到输入是 JSON 时直接走 API 分支，跳过 HTML 流程。
- 找到 API 的技巧：用 `agent-browser eval "performance.getEntriesByType('resource').map(r=>r.name)"` 抓 SPA 真实请求。

### 3.1 浏览器驱动抓取的四个坑（2026-09-07 实测，重要）
1. **agent-browser 是单会话共享资源**：后台 eval 循环抓 A 站期间，前台 `agent-browser open` B 站会把 origin 切走，循环里相对路径 `fetch('/api/...')` 全打到 B 站域名（错误被 `catch(e){}` 吞掉 → 输出空/`[]`，极易误判为"0 命中"）。**后台浏览器任务运行期间禁止导航其他站**；脚本开头必须先 `open` 回目标域名。
2. **eval 输出是转义 JSON 字符串**：`eval` 返回 JSON.stringify 结果会带外层引号+`\"` 转义，bash 里 `grep '"projectId"'` 计数为 0 是假象——必须在 Python 里 `json.loads` 两层解析后统计。
3. **大 chunk eval 会超时**：一次 eval 循环 fetch 8+ 页可能触发连接超时（os error 10060）且**部分成功部分丢**（chunk 文件 0 字节）。稳妥做法：每 chunk ≤4 页，0 字节 chunk 单独补抓，并用"返回长度"校验。
4. **联交所详情接口对雪花 ID 项目返回"项目不存在"**：列表里 `projectId` 为 17855... 长雪花 ID 的多为"分零/分包"子项目，`projectDetailQuery?id=` 查不到，只能官网页面看；普通短 ID（如 202473）正常返回。

## 3.5. 公拍网 上海搜索实测（2026-09-03 落地，重要）
- **上海本地主源是公拍网（gpai.net），不是阿里法拍**：阿里 `category=50025969` 默认信息流**重庆主导**（80 页仅 13 套上海、0 静安）；其上海城市页 `list/50025969____<GBK城市名>.htm` 返回**人机验证墙(captcha)**，自动化不可行。故上海类需求走公拍网。
- **会话 + 搜索 + 分页（缺一不可）**：
  1. 先 `GET https://s.gpai.net/sf/` 建立会话 cookie（否则 `search.do` 302 重定向墙）。
  2. 关键词搜索：POST `https://s.gpai.net/sf/Search.do`，表单字段是 **`q=静安`**（不是 `keyword`！前者才真过滤，后者返回默认页）。
  3. **分页参数是 `page` 不是 `pageNo`**：`Search.do?q=静安&page=2` 才换页；`pageNo=2` 返回首页重复内容。
  4. 司法拍卖/变卖列表：`search.do?action=court` / `?action=selloff`（同样需先建 cookie）。
- **列表块结构**：`<div class="list-item">` → 标题在 `item-tit>a`，价格 `起拍价：<b>xxx</b>元` / `评估价：<b>xxx</b>万元`（已成交项显示 `成交价` 而非 `起拍价`）。
- **详情页**：`https://www.gpai.net/sf/item2.do?Web_Item_ID=<ID>` 服务端渲染可达（~60KB），含 `id="Price_Start"`（起拍价元）、评估价、面积、房屋类型；个别 ID 返回 **412 Precondition Failed**（标的已失效），须跳过。
- **户型(室厅)缺口**：公拍网列表/详情普遍只给建筑面积+用途，不列室厅数；精确户型须走人工取证源（用户提供 HTML → 本地解析）或实地看样。

## 3.6. 阿里法拍 区域/关键词筛选失效（2026-09-03 实测，重要）
- **现象**：上海静安需求下，阿里 `item_list.htm` 抓到的全是**重庆主导的全国默认流**（静安命中 0/60）；区域路径 `list/50025969____上海.htm` 返回**人机验证墙(captcha)**。
- **根因（已定位）**：
  1. `item_list.htm?category=50025969&page=N`（不带 keyword）→ 返回全国房产默认流，**category 参数被忽略**。
  2. `item_list.htm?keyword=静安&category=50025969` → **keyword 参数同样被忽略**，仍返回上述全国流（静安 0/60）。`keyword=静安&province=31` / `q=静安` 变体要么空（条目 0）要么退回全国流。
  3. 真正的前端搜索是 `list/0____.htm?keyword=静安` 这个 **JS 壳页（~59KB，UTF-8）**，数据靠前端调用**签名 mtop/JSON API** 动态加载，urllib 直连拿不到筛选结果。
  4. **编码坑**：`item_list.htm` 返回的 HTML 实际是 **GBK 编码**（不是 UTF-8）。若按 UTF-8 解码，中文标题变乱码、本地"静安"过滤全部失效——这正是早期 0 命中的隐藏原因。须用 `raw.decode("gbk","ignore")`。
- **结论**：纯 urllib 自动抓阿里**区域/关键词**筛选结果**不可行**（签名 API + 验证码墙）。可行方案只有两条：
  - (a) 抓全国默认流 → 本地按标题含"静安/上海"过滤（但全国流里上海静安本就极少，召回差）；
  - (b) 用 agent-browser 驱动真实浏览器过验证 + 抓签名 API（重，但准）。
  - **更优解**：上海本地需求直接走**公拍网**（gpai.net，上海法院官方司法拍卖平台，与阿里挂同一批标的），无需硬刚阿里。
- **修正历史误判**：此前认为"阿里上海城市页 captcha 是唯一障碍"，实测发现即便绕开 captcha，默认流也不含静安、keyword 被忽略——核心是**搜索接口未对直连开放**。
- **2026-09-03 浏览器自动化实测补丁**：用 agent-browser 开 `item_list.htm?category=50025969` 能公开加载（无登录）；但**任何筛选动作都触发淘宝登录墙**：
  - 直访 `list/0____.htm?keyword=静安` → 重定向 `login.taobao.com`。
  - 页面上点"所在地-上海"按钮（`ref=e160`） → 同样弹回登录页。
  - **唯一公开可访问的是无筛选的全国默认信息流**（重庆主导，静安=0）。
  - **不可行路径**：请求用户 淘宝/支付宝 登录 cookie 注入 agent-browser —— 涉及完整账户会话（含支付），属敏感凭据，**禁止**这么做。
  - **真实可行的策略**：报告里如实写"阿里筛选需登录、未纳入"，并指出上海静安已通过公拍网（与阿里同源镜像）完整覆盖。

## 3.8. 重庆江北/渝北需求实测（2026-09-07，重要——重庆是本技能最佳服务区）
- **阿里全国流对重庆江北/渝北召回极好**：40 页 2400 条中命中 277 条（约 11.5%），首页即 13 条。重庆类需求**首选阿里法拍**，本地过滤即可，无需硬刚筛选参数。

## 3.9. 性能优化重构（2026-09-07 · 提速 + 提准，已完成）

**旧流程痛点**：① 每页 fork 2 次 Python 子进程（`fetch_page.py`+`extract_page.py`），40 页纯进程开销 ~29s；
② 手工串联易漏抓（翻页后注入函数丢失 / 跨域 fetch 打错站 → 静默丢数据、误判 0 命中）；
③ 易混入「外地同名区」（重庆北碚「北京路」误判为北京）；④ 易把车位/商铺当住宅。

**新增模块（见 SKILL.md §9 调用示例）**：
- `ph_core.py`：城市感知区县匹配（`match_district` 需城市前缀或标题以区名开头，拒绝外地同名区）、`is_residential` 非住宅剔除、`dedup_by_fingerprint` 跨源去重、`score_listing` 统一评分。
- `batch_ali.py`：进程内解析（复用 `extract_listings`）+ 页面缓存（24h 同源不重抓）+ 早停（连续 8 页无命中停）+ 可调限速。
- `run_search.py`：一键编排（阿里批量 + 联交所并入 + 标准化 + 双版本报告）。
- `browser_sweep.sh`：浏览器扫站器，空块自动重试。
- `benchmark.py`：速度基准。

**基准实测（267KB 阿里列表页样本）**：
- 解析加速比 **11.2x**（0.358s/页 → 0.032s/页，纯 Python 开销）。
- 含抓取子进程的全链路：40 页进程启动开销节省 **~96%**（~29s → ~1s）。
- `ph_core --self-test` 通过：宁波江北区（外地同名区）正确拒绝、重庆江北区正确接受；车位/办公/负楼层正确判非住宅。

**京东法拍（待办）**：用户在 2026-09-03 要求"把京东法拍加载回去"。北京任务期间已探明浏览器路径 `auction.jd.com/sifa.html`（公开可访问，含北京地域/住宅筛选）→ `pmsearch.jd.com/?publishSource=7&provinceId=1&cityId=<区ID>`（朝阳=72），但 `countyId` 参数名不对、真实筛选走 SPA 状态（点击 UI 后朝阳住宅=57 件）；`sifa.jd.com` 强制登录、`paimai_unifiedSearch` 带 h5st 签名（按 R1 不逆向）。**该源尚未脚本化**，北京类需求目前仍建议人工浏览 sifa.jd.com。

## 5. agent-browser 使用要点
- `html` 子命令**不存在**；导出文本用 `snapshot`（无障碍树）。
- 有用子命令：`open` / `wait --load load` / `wait <ms>` / `snapshot` / `eval <js>` / `get url` / `find text` / `click` / `type`。
- 抓 SPA 背后真实接口：`eval` 跑 `performance.getEntriesByType('resource')` 或 `document.querySelectorAll('[href]')`。
- 渲染重 SPA 时 `wait --load load` 后**再 `wait 3000+`** 等 JS 填充。
- 导航若是 Vue router（非 `<a>` 标签），`snapshot` 不暴露 href、文本选择器 `click "项目中心"` 会失败 → 改用 `eval` 拿 API。

## 6. 工作流（标准调用顺序）
```
1. fetch_page.py  <URL>            # 合规抓取（robots 检查 + 限速 + 反爬识别）
2. extract_page.py --html <file> --site <源> [--judicial-only] [--out ...]
                                     # 结构化提取
3. download_assets.py              # 户型图/评估报告附件（可选）
```
- **多平台交叉核验是必须**：同一标的在不同平台信息完整度差异极大。
- 人工取证源：用户自己浏览器打开 → 复制页面 HTML → 交给 `extract_page.py` 本地解析（不发任何网络请求）。

## 9. 用户如何精准提问（直接照搬给用户，减少来回澄清）
> 提问公式 = **指定源 + 明确筛选条件 + 指定产出 + 是否交叉核验**。（完整版在 SKILL.md §2.1）

1. **指定源（最重要，各源能力不同）**
   - 能自动抓：说「阿里法拍 / 公拍网 / 重庆联交所」
   - 不要说「去所有网站找」，而是点名哪几个
2. **明确筛选条件**：地域（重庆市渝中区）、用途（住宅/商铺/车位/厂房）、价格（起拍价 50万-200万）、面积/户型（90平以上三房）
3. **指定产出**：只要链接和起拍价 / 完整尽调报告 / 要户型图和公告原文 / 导出表格或 HTML
4. **是否交叉核验**：只在阿里法拍找 / 三个平台交叉比对同一标的

**反例**：「帮我找个便宜的房子」→ 无法执行，必须点名源 + 条件 + 产出。
**关键认知（用户已确认）**：本技能收的是**拍卖/资产处置类标的**（法拍/国资/社会拍卖），**普通二手房不接入**，别用本技能找二手商品房。
